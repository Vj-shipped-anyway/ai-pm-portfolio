# Data for project 46

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Nothing here comes from a real cloud account, Terraform run, bank or employer. The account number `111122223333` and the other identifiers are made up.

| File | What it holds |
|---|---|
| `plans.csv` | 86 plans: `plan_id`, `plan_json` (a Terraform plan in JSON form, reduced to the parts `plan_guard.py` reads) |
| `plan_truth.csv` | The planted change per plan: `kind`, `truth_class` (block, review, ok), `target_address` (the planted resource) and `expected_rule`. The label comes from the change that was planted, not from the rules |
| `example_plan.json` | The worked example behind `python3 plan_guard.py --demo`: seven resource changes, two blocking findings, two reviews, one delete that is ignored |

Each plan holds `format_version`, `terraform_version` (the placeholder `1.x-synthetic`) and `resource_changes`. Each change has `address`, `mode`, `type`, `name`, `provider_name` and `change` with `actions`, `before`, `after` and `after_unknown`. A plan has two to five clean resources around the planted one, some inside a module address.

Planted changes (86 plans). Need a look (10): plain HTTP listener 3, encryption value unknown until apply 4, bucket policy unknown until apply 3. Harmless (34): no planted change 8, world-open port 80 or 443 4, private CIDR on an admin or database port 3, Deny policy for everyone 3, policy for everyone limited to one VPC endpoint 3, HTTP listener that redirects to HTTPS 3, deleted risky resource 4, unchanged risky resource 3, HTTP listener on an internal load balancer 3. The last one is a decoy: the rules raise a review on it because they never join two resources.

## Assumptions (🟡 modeled, not taken from a standard or a regulation)

- Admin ports 22 and 3389. Database ports 1433, 1521, 3306, 5432, 6379 and 27017.
- The canned ACLs `public-read`, `public-read-write` and `authenticated-read` count as public.
- An encryption flag that is false, null or absent is read as off; a flag marked unknown after apply is read as unverified. A real provider may report an unset attribute in any of these ways, and the plans use all three. Not checked against a real Terraform run.
- Severity: nine rules are high (BLOCK), the plain HTTP listener rule is medium (REVIEW).
- The plan shape is the subset of `terraform show -json` that I know; I did not re-read the format documentation or compare against real output.
