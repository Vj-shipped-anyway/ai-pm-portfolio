# Data for project 75

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Nothing here comes from a real merchant, customer, bank or card network.

| File | What it holds |
|---|---|
| `rules.json` | The evidence list: 6 reason codes, each with a response window and a list of evidence items (some either-or, some optional), plus the page limit and two document-type lists. 🟡 Every value is an assumption invented for this prototype. They are not any card network's reason codes, lists or deadlines |
| `cases.json` | 100 dispute cases. Each has `case_id`, `reason_code`, `order_id`, `txn_date`, `received_date`, `amount_cents`, `submitted_date` (empty while the packet is a draft) and `docs`: `doc_id`, `doc_type`, `ref_id`, `doc_date`, `pages`, and `amount_cents` on order records and billing histories |
| `case_truth.csv` | The planted fault per case: `planted_kind`, `truth_class` (ready, defective, late) and `visible_in_metadata`. The label comes from the fault that was planted into a good packet, not from the checker |
| `as_of.txt` | The date of the check for every draft packet: 2026-03-31 |
| `example_case.json` | The worked example behind `python3 chargeback_packet.py --demo` (a not-received dispute with no delivery proof, checked on 2026-02-28) |

Assumptions (🟡), all in `rules.json`:

- Reason codes RC-01 to RC-06 and their names are invented.
- Response windows, counted in calendar days from the day the dispute was received, with the last day counting: RC-01 20, RC-02 30, RC-03 30, RC-04 14, RC-05 21, RC-06 30. No weekend or holiday rule.
- Evidence items per code, which are required and which are optional, and which document types may stand in for each other.
- The page limit for a packet: 12.
- Which document types cannot be dated before the purchase (signed receipt, delivery tracking, digital access log, refund record), and which carry an amount that must cover the disputed amount (order record, billing history).

Planted cases (100), by truth class:

- ready 43: plain and sent on time 17, second option of an either-or item 8, partial dispute (order total above the disputed amount) 5, sent on the last day 5, draft with the window open 5 (two of them due today), extra document on no list 3. The last five kinds are hard negatives: they look short, late or odd and are fine.
- defective 43 (the clock is still running): required item missing 10, a document names another order 6, order record below the disputed amount 5, post-purchase document dated before the purchase 5, a document dated after the check date 3, over the page limit 5, and two kinds that are hard misses on purpose: a document that belongs to another case 6 and an unreadable scan 3. The checker reads labels, dates, references, amounts and page counts, so it cannot see the last two.
- late 14: sent after the window 7, draft past the window 4, sent late and also missing a required item 3.

The recipe for a good packet in `_generate.py` is written separately from the slots in `rules.json`, so a mistake in one shows up as a false alarm on a good packet. Both were written by the same author. Results on this data are a ceiling for these rules, not a rate on real disputes.
