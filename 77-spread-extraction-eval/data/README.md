# Data for project 77

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Company names are invented. Nothing here comes from a real filing, customer, bank or employer.

| File | What it holds |
|---|---|
| `statements.csv` | 120 statements: `doc_id`, `layout`, `split` (`dev` or `holdout`), `company`, `text` (an income statement and a balance sheet as plain text) |
| `truth.csv` | 5,280 true values: `doc_id`, `field`, `period` (current or prior), `value`. 22 fields in 2 periods per statement, in whole dollars |

Layouts, 20 statements each:

| Layout | Split | What is different |
|---|---|---|
| `plain_two_column` | development | Label, current year, prior year. Minus sign for a negative. The layout the first extractor was written against |
| `thousands_parens` | development | Figures in thousands of dollars, stated once under the title. Prior year first. Parentheses for a negative, a dash for zero, a dollar sign on some rows |
| `relabelled` | development | Different line names (net sales, finance costs, profit for the year, trade receivables) |
| `side_by_side` | development | The balance sheet prints assets on the left and liabilities and equity on the right, in the same lines |
| `wrapped_footnotes` | development | Dot leaders, footnote markers after four labels, long labels wrapped onto two lines |
| `note_column` | holdout | A column of note numbers sits between the label and the values, filled on 7 rows |

Every statement satisfies ten accounting identities in both periods (gross profit = revenue less cost of sales, assets = liabilities plus equity, and so on). Truth comes from the generator that builds each company, not from either extractor. Four of the 20 statements in each layout are loss-making, and one slot per layout is built with heavy long-term debt, which gave negative equity in 5 of the 6 layouts. Statements printed in thousands have truth values that are multiples of 1,000.

`development` and `holdout` mean one thing: the stand-in extractors in `src/_standins.py` have rules for the five development layouts and none for `note_column`. The same author wrote the generator, so the holdout is a planted miss, not a surprise.

Assumptions (🟡): the gate limits are not from any source. The defaults are a floor of 95.0% field accuracy, a gap of 3.0 points to the best layout and at least 10 statements per layout. A value is right within half a dollar.
