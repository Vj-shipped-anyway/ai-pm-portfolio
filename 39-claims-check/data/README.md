# Data for project 39

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Nothing here comes from a real README, repository, bank or employer. No parameter comes from a regulation or standard.

| File | What it holds |
|---|---|
| `projects.json` | 40 made-up projects: `project_id`, `readme` (the text, with green, yellow and red bullets) and `evidence` (what that project's scripts printed) |
| `truth.csv` | One row per green or tagged bullet, 284 in all: `project_id`, `line_start`, `line_end`, `kind`, `expected` (`ok` or `flag`). The label comes from how the bullet was built, not from the checker |
| `example_claims.md`, `example_output.txt` | The worked example behind `python3 claims_check.py --demo` |

Planted bullets that are fine (186): exact 90, comma 12 (README and output differ only in thousands commas), trailing_period 12, trailing_zero 10 (25 against 25.0), inert_digits 24 (digits in a code span or a link target), wrapped_ok 10 (a second line that carries a printed number), not_green 12 (a yellow or red tag with an unprinted number), small_numeral 8 (a stray one-digit numeral), pair_split 8 (both numbers printed, on separate lines).

Planted bullets that are wrong (98): typo 14, stale 14, invented 10 (no line prints the metric), substring_trap 14 (the number is a piece of a longer printed one), rounded 8 (40 against 40.3), pair_broken 12 (both numbers printed, never together), wrapped_bad 8 (a wrong number on the second line of a bullet), coincidence 10 (a wrong number that equals another printed number), single_digit 8.

Seven kinds are hard on purpose. substring_trap, rounded, pair_broken and wrapped_bad pass a grep and fail the whole-number rules. pair_split is a fine bullet that the pair rule flags. coincidence and single_digit pass every rule in `src/`.
