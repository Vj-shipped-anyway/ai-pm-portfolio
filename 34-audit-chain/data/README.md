# Data for project 34

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Nothing here comes from a real agent, bank or employer. Names such as `reviewer.3` and `C0007` are made up.

| File | What it holds |
|---|---|
| `actions.csv` | 280 agent actions over 36 cases: `case_id`, `step`, `kind`, `actor`, `detail_json`. The kinds are the ones the AgentKit audit module writes. Some notes carry accented characters on purpose |
| `tamper_plan.csv` | 101 planted edits: `tamper_id`, `op`, `seq` (the first event the edit touches), `count`, `region`, `truth`. `truth` is `tampered` or `benign` and comes from what the plan does to the file, not from any check |
| `params.json` | The seed, the number of cases and events, and `anchor_seq` |
| `example_log.jsonl`, `example_log_edited.jsonl`, `example_log_cut.jsonl`, `example_anchor.json` | The worked example behind `python3 audit_chain.py --demo`: the first 30 events, the same log with one approval flipped, the same log cut to 20 events, and an anchor taken at event 24 |

The log itself is not stored: `src/common.py` builds it from `actions.csv` with the audit module. `_generate.py` has its own small hash writer, so the verifier is tested against a log it did not write.

**Anchor interval.** 🟡 Assumption: one anchor, at event 200 of 280. No rule sets this number. It splits the planted edits into those that touch an anchored event (`region` = `anchored`) and those that only touch the open tail after it (`open`).

**Planted edits (101).** Anchored region, 64: value changed 8, value changed with its own hash recomputed 8, line deleted 6, event deleted with later events renumbered and re-hashed 6, two neighbours swapped and fixed up 6, forged event inserted and fixed up 6, duplicate key 5, field outside the hash 5, full rewrite with every hash recomputed 8, log cut below the anchor 6. Open tail, 27: value changed 4, value changed with its own hash recomputed 5 (one of them the last event), full rewrite 4, duplicate key 2, field outside the hash 2, log cut but all anchored events kept 4, forged events appended 6. Benign, 10: keys reordered, characters written raw, Windows line endings, blank lines (one each), and events appended by the real writer after the anchor 6.

Hard on purpose. Edits a hash chain cannot see: the last event rewritten with its own hash recomputed, a rewrite or a cut that stays in the open tail, events appended by someone who knows the algorithm. Harmless changes that could raise a false alarm: the four rewrites of the file's form and the legitimate appends. The same author wrote the plan and the checks, so the results are a ceiling for these checks, not a rate on real logs.
