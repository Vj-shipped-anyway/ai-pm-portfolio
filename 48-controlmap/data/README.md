# Data for project 48

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Nothing here comes from a real bank, control library, regulator file or employer. The obligation statements and control descriptions are sentences I wrote for this exercise; they are not the text of any rule or framework.

| File | What it holds |
|---|---|
| `obligations.csv` | 56 obligations: `obligation_id`, `source` (an internal document type), `theme`, `statement`, `applies_to` (use-case classes), `claimed_controls` (the hand-typed column the status quo relies on; the tool does not read it) |
| `controls.csv` | 55 controls: `control_id`, `name`, `description`, `owner`, `scope`, `test_cycle_days`, `last_evidence_on`, `status` (51 active, 4 retired) |
| `terms.csv` | The theme dictionary: 31 phrases across 11 themes. One theme (model retirement) has no row on purpose |
| `control_truth.csv` | The planted truth per control: the theme it serves (empty when it serves nothing) and its `kind` |
| `truth_pairs.csv` | 175 (obligation, control) pairs where an active control serves the obligation's theme, with the scope label full (71), partial (61) or none (43) |
| `truth_status.csv` | The planted status per obligation: COVERED 19, STALE 16, PARTIAL 13, UNCOVERED 8 |
| `dataset.json` | The as-of date (2026-06-30), the class list, the freshness multiplier and the seed |
| `example_*.csv` | The worked example behind `python3 controlmap.py --demo`: 6 obligations, 6 controls, 6 dictionary rows |

Everything the tool reads is in the first three files. The truth files exist only because the data is synthetic.

## How the truth is made

The generator gives each control a hidden `serves_theme`. The truth pairs and the truth status come from that field, from the scopes and from the evidence ages, through a status function in `_generate.py`. The rules in `src/controlmap.py` never read the hidden field. Two definitions are shared by construction, so agreement on them is not evidence: scope (a control covers an obligation fully when it runs in every class the obligation applies to) and freshness (evidence is fresh when it is no older than 1.5 test cycles at the as-of date). 🟡 The 1.5 multiplier and the as-of date are assumptions I chose, not values from any rule.

## Control kinds (55 controls)

| Kind | Controls | What it tests |
|---|---|---|
| `dict` | 27 | Serves a theme and uses a dictionary phrase: the normal case |
| `off_dictionary` | 6 | Serves a theme in words the dictionary does not list: a miss for the rules |
| `negated_true` | 1 | Serves a theme but says "no exception to human review": the negation rule drops it |
| `negated_decoy` | 3 | Serves nothing and mentions a dictionary phrase only to deny it |
| `wrong_sense` | 2 | Serves nothing but uses a dictionary phrase in another sense: a false link the rules cannot see |
| `lookalike` | 4 | Serves nothing but shares ordinary words with obligations: a trap for a keyword sheet |
| `orphan` | 6 | Serves nothing and shares no words with any obligation |
| `retired` | 4 | Served a theme once; status retired |
| `unlisted_theme` | 2 | Serves the theme that has no dictionary row |

## Obligations

12 themes: model inventory 5, independent validation 5, ongoing monitoring 5, human oversight 5, change management 5, vendor model oversight 5, data quality 5, user disclosure 4, fairness testing 5, incident response 4, decision explanations 4, model retirement 4. Each obligation applies to 1 to 3 of 5 use-case classes. Two themes have no active control (incident response; decision explanations, whose controls are retired), and every control for vendor model oversight has evidence older than its limit.

## The typed column

`claimed_controls` is produced by a separate seeded process: each true control is typed with probability 0.6, a retired control of the same theme is added half the time, a wrong active row 15% of the time and a renumbered id (CT-9nn, not in the library) 8% of the time. 🟡 Those rates are assumptions; they set how bad the status quo is, so read the step 1 numbers as an example, not as a finding about real registers.
