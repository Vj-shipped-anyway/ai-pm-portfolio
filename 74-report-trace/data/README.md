# Data for project 74

Synthetic. Generated by `_generate.py` with a fixed seed and integer arithmetic only, so a rerun reproduces every file byte for byte. Nothing here comes from a real bank, customer, employer or regulator's form; the report is an invented loan schedule.

The loan table is a position table for one reporting date, 2026-06-30. It is corrected in place, later loans are appended with their own booked dates, and it is not updated by payments. Closed loans keep their last balance and days past due.

| File | What it holds |
|---|---|
| `loans_filed.csv` | 3,687 loans as they stood when the report was filed: `loan_id`, `product`, `status`, `booked_date`, `days_past_due` (blank on 7 open loans), `balance_cents`, `servicer_note` |
| `loans_now.csv` | The same table months later: 3,724 rows after corrections, deletions and appended loans |
| `report_spec.json` | The report: 8 products, 6 days-past-due buckets, 71 cells. A leaf cell names a product and a bucket. A derived cell lists its inputs explicitly (row totals, column totals, a grand total, a past-due share in basis points) |
| `report_filed.csv` | The value filed for each cell, in cents (basis points for the ratio cells) |
| `adjustments.csv` | 4 logged top-side adjustments: `adj_id`, `cell_id`, `amount_cents`, `reason` |
| `mapping_sheet.csv` | The team's documentation of each leaf cell as a filter on the loan table: product, days-past-due range, status. It has no as-of date and no adjustment column, which is how such sheets usually read. Used by steps 1 to 3 |
| `truth_cells.csv` | The planted class of every cell. The label comes from what the generator did, not from any check |
| `truth_rows.csv` | The loans the generator touched, per cell and kind, plus the 7 blank-days-past-due loans |
| `example_*` | A 41-loan, 14-cell set behind `python3 report_trace.py --demo` (one unlogged amount, one restated balance, one logged adjustment, one note edit, three loans booked after the as-of date) |

## Rules of the report

A leaf cell is the sum of `balance_cents` over open loans of one product, booked on or before the as-of date, whose `days_past_due` falls in the bucket. The buckets are current (0), 1 to 29, 30 to 59, 60 to 89, 90 to 179 and 180 or more. These are invented for the exercise and taken from no rule.

## Planted classes

Leaf cells (48): clean 6; logged adjustment 4; unlogged amount 4; one balance restated after filing 5; one row deleted after filing 3; one or two loans booked before the as-of date but loaded after filing 3; two balances changed by equal and opposite amounts 3; one source row with a wrong but plausible days-past-due 4; only the servicer note edited on two rows 4; three loans booked after the as-of date appended 12.

Derived cells (23): foots 20; footing error 3 (a row total, a column total and a ratio, each shifted after its inputs were summed).

Hard on purpose: offsetting changes keep the cell sum; a note edit and loans booked after the as-of date are harmless changes a naive check would flag; the wrong source row is a problem no lineage check can see, and it is the known limit.

The filed values come from the generator's own aggregation (a bisect on bucket edges), which is separate from the cell rules in `src/report_trace.py`.
