# Sample Data — PolicyNeedle walkthrough

Four synthetic policy manuals and the question set that goes with them. Everything here is invented and generated by [`_generate.py`](./_generate.py): standard library only, seeded, deterministic. Running it twice writes byte-identical files. No real institution, customer, product, vendor or incident is described. The manuals are written so that an assistant has to read them, not so that they read like any particular bank's.

To regenerate:

```bash
python3 data/_generate.py
```

One synthetic "page" is 1,800 characters (about 300 words). That is a convention of this repo, not the layout of any real manual. Lengths are counted in characters.

## `manuals/` and `manuals.csv` — four manuals

| manual_id | chars | approx pages | sections | blocks | planted facts | amendment register starts at |
| --- | --- | --- | --- | --- | --- | --- |
| `manual_006p` | 10,605 | 5.9 | 4 | 95 | 10 | none |
| `manual_040p` | 72,102 | 40.1 | 16 | 654 | 90 | char 68,613 |
| `manual_120p` | 216,553 | 120.3 | 43 | 1,840 | 90 | char 209,428 |
| `manual_240p` | 432,391 | 240.2 | 83 | 3,616 | 90 | char 420,044 |

`manual_006p` is the short excerpt for the Step 1 spot test: plain clauses only, no amendment register. The other three are the long manuals.

**Layout.** A manual is plain text. Blocks are separated by one blank line: a front-matter block, section headings (`Section 7. Card Services Procedures`), numbered clauses (`7.12 ...`), tables (a caption line, a header row and product rows, all in one block), footnote notes (`Note to clause 7.12: ...`) and, in the long manuals, `Appendix A. Amendment Register` followed by numbered amendments sorted by effective date. The front matter says an amendment in Appendix A governs over the clause it replaces and that a note applies to the clause it cites. Every amendment is effective on or before the issue date (2026-07-01).

Most of each manual is filler: procedural clauses generated from word lists, with no product names and none of the words a question uses. The planted facts are the part that matters.

**Depth.** Depth is how far into the manual body a fact sits: 0% is the first section, 100% is the end of the body, just before the closing Document Control section and the amendment register. Each depth label is a band: planted facts for one depth sit close together, so the actual position (`position_pct`) can differ from the label by a few percent.

## `probes.csv` — 280 probes with exact expected answers

| Field | Description |
| --- | --- |
| `probe_id` | Stable identifier, for example `L120-SUP-050-1` (set L = long sweep or S = short test, 120 pages, form SUP, depth 50, replicate 1). |
| `probe_set` | `short_spot` (10 probes, Step 1) or `long_sweep` (270 probes, Steps 2 to 4). |
| `manual_id`, `length_pages`, `doc_chars` | Which manual the question is asked against. |
| `form` | One of six: `plain`, `superseded`, `exception`, `table`, `two_section`, `distractor`. |
| `depth_pct` | Nominal depth label: 0, 25, 50, 75 or 100. |
| `position_pct` | Where the primary clause actually starts, as a percent of the whole document (the register at the back is included in the denominator). |
| `question` | The question text. |
| `expected_answer` | One exact answer: a dollar amount, a percent, a number of days, or `yes` or `no`. |
| `answer_kind` | `money_limit`, `money_fee`, `percent`, `days` or `yes_no`. |
| `evidence_start`, `evidence_end` | Character offset of the primary clause, and the end of the last block the answer needs. A reader that sees only the first N characters can answer only if `evidence_end <= N`. |
| `evidence_spans` | Every planted block for the probe: role and character range. |
| `trap_label`, `trap_answers` | The wrong answer the form invites, and its values. Used to name the kind of wrong answer. |
| `scoring` | `exact` (normalized exact match). |

**The six forms.** Per cell (form × length × depth) there are 3 probes, so 90 cells and 270 long-sweep probes.

| Form | What is planted | The trap |
| --- | --- | --- |
| `plain` | One clause: `For Kite Mortgage, the bonus rewards rate is 2%.` | None. Only position can hurt. |
| `superseded` | The clause at depth, and an amendment in Appendix A, at the back, that replaces it. Expected answer is the amended value. | The original value (`stale_version`). |
| `exception` | A clause that says a fee is charged when an event happens, and a footnote that says it is not charged when the event has a reason. Two of three probes per cell ask about a covered reason (expected `no`); one asks about a reason the footnote does not cover (expected `yes`). | `yes` for the covered case (`exception_missed`); `no` for the uncovered case (`exception_over_applied`). |
| `table` | A tier table; the question names Tier 2 or Tier 3. | The first column's value (`wrong_column`). |
| `two_section` | A standard fee in one section and, in the next section, a discount clause for the product (25% or 50% off). Expected answer is the computed fee. | The discount percent or the standard fee alone (`single_clause`). |
| `distractor` | The true clause for a product, with clauses for two sibling products (same brand and type, a modifier word added) directly before and after it. | A sibling's value (`sibling_answer`). |

**Probe audit.** Every question must match exactly the blocks its form is built around under the keyword rule the stub readers use (a block holds at least 4 of every 5 of the question's content words): 1 block for plain and table and two-section, 2 for superseded and exception, 3 for distractor. The generator re-draws a manual until the audit passes, and `step_04_with_policyneedle.py` re-runs the audit with the harness's own copy of the rule. The result is 0 ambiguous probes of 280.

## `probe_types.csv` — what the harness can and cannot score

11 probe types. Six are the forms above, which exact match can score. Five are types a real assistant would face and exact match cannot score: `paraphrased_answer`, `unit_converted_answer`, `verbose_or_hedged_answer`, `multi_value_answer`, `free_text_explanation`. They have `n_probes = 0` because the set contains none of them. That is the known limit, printed by Step 4.

## How the files connect

```
_generate.py ──┬──>  manuals/*.txt         (the documents a reader is given)
               ├──>  manuals.csv           (one row per manual)
               ├──>  probes.csv ─────────> src/harness.py: run, score, slice, gate
               └──>  probe_types.csv       (which types exact match can score)

src/step_01 uses probes where probe_set = short_spot
src/step_02 uses the long_sweep probes with form = plain and depth = 50
src/step_03 and step_04 use all 270 long_sweep probes
```

Reproducibility: every measured (🟢) number in the README, the demo and the app is printed by a script that reads these files. Regenerate the data, rerun the scripts, and the output matches to the digit.
