# Data for project 69

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Nothing here comes from a real bank, product sheet, customer or employer. The bank is fictional and no product name is a real one.

| File | What it holds |
|---|---|
| `kb.csv` | The knowledge base: 12 passages with `fact_id`, `product`, `excluded_states` (semicolon-separated state names where the product is not offered) and `text` |
| `queries.csv` | 30 customer questions: `query_id`, `topic` (deposit 10, lending 15, general 5), `q_class`, `question`, `correct_answer` |
| `drafts.csv` | One stored draft per question. These stand in for a chatbot's draft; no model wrote them |
| `truth.csv` | The planted label per draft: `fact_id` (the passage that answers the question, blank when none does), `draft_mode`, `draft_ok`, `should_serve`, `hard_case`. The label comes from how the draft was written, not from the gate |

Question classes (30): answerable 14, not_in_kb 6, out_of_scope 4, state_specific 3, ambiguous 3.

Planted draft modes (30): faithful 9, faithful_words 1 (correct, but the number is spelled out), wrong_slot 3 (a number from the right passage that answers a different question), wrong_number 2, invented 4 (a number or fact the passage does not have), negation_flip 1, fake_citation 1, wrong_state 1, advice 3, picks_one 3 (one product chosen for an ambiguous question), decline 2 (the draft hands off on its own). Ten drafts are correct and should be served; 18 are wrong; 2 decline.

Hard cases, set by the generator and not by the gate: 6 hard negatives (correct drafts a rule could flag: a number written as `$10,000.00`, a correct "no" in a passage with other negative words, a number spelled out, a "should I" in an answerable question, a correct answer that names other states) and 3 hard misses (wrong_slot drafts that quote a real number).

Each draft variant is chosen by a hash of the seed and the question id, not by `random`, so the files do not depend on the Python version.

Extends the shape of project 01-halluguard-bank-chatbot-safety (30 questions, an eval set built from failure cases, abstention to a banker). Nothing was copied from its files.

Units and meaning are not modeled in the data. The 12 passages are short on purpose; a real knowledge base is longer and messier.
