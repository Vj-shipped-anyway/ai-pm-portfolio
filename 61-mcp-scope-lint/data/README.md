# Data for project 61

Synthetic. Generated by `_generate.py` with a fixed seed (`SEED = 61`), so a rerun reproduces every file byte for byte. Nothing here comes from a real server, tool catalogue, bank or employer. The generator uses only the Python standard library.

| File | What it holds |
|---|---|
| `manifests.json` | 30 manifests (`synthetic-mcp-01` to `synthetic-mcp-30`), 218 tools, 234 granted scopes, 484 catalog entries. Shape: `server`, `scope_catalog`, `granted_scopes`, `tools` |
| `entitlement_truth.csv` | 260 rows, one per specific scope the grants reach (wildcards expanded): `server`, `scope`, `needed` (yes or no), `planted` (the profile of its resource) |
| `tool_scope_truth.csv` | 247 rows, one per scope a tool declares: `server`, `tool`, `scope`, `needed`, `planted` (the profile of the tool) |
| `example_manifest.json` | The manifest behind `python3 mcp_scope_lint.py --demo`: 5 tools, 5 granted scopes |
| `example_clean.json` | A manifest with no findings: 3 tools, 3 granted scopes |

**The truth is known because the data is synthetic.** The generator builds each resource from a profile. A profile fixes which tools exist, which scopes they declare, which scopes they truly need and whether anyone calls them. `needed` is yes when a tool that is called truly needs the scope. No rule reads the truth files; the steps use them to score.

A manifest shape note: `requires_scopes` on a tool and `granted_scopes` are my own fields, and the hints `readOnlyHint` and `destructiveHint` are the tool author's claim. About a quarter of ordinary tools are written with no annotations (`NO_HINT_SHARE`). A tool with a destructive hint is not checked either, since that hint sets no ceiling.

## Profiles (resources: 122 in all)

Each server has 3 to 5 resources. 73 of the 122 carry a planted profile; 49 are clean (read tools, sometimes a write tool, every granted scope used).

| Group | Profile (resources) | What is built | Truth |
|---|---|---|---|
| Caught | `unused_specific` (12) | clean, plus one granted write or delete scope no tool uses | extra scope not needed |
| Caught | `unused_wildcard` (5) | a wildcard granted on a resource with no tool | all its scopes not needed |
| Caught | `wildcard_partly_used` (8) | a wildcard granted; tools use read, sometimes write | the rest not needed |
| Caught | `read_tool_write_scope` (9) | a tool with a read-only hint declares read and write | write not needed |
| Caught | `read_tool_wildcard` (5) | a tool with a read-only hint declares the wildcard | write and delete not needed |
| Caught | `nondestructive_tool_delete` (4) | a tool with a non-destructive hint declares write and delete | delete not needed |
| Caught, not narrowed | `wildcard_nohint` (4) | a tool with no hint declares the wildcard | write and delete not needed |
| Missed | `overscoped_nohint` (6) | a tool with no hint declares read and write | write not needed |
| Missed | `overscoped_wrong_hint` (4) | a tool hinted non-destructive declares read and write | write not needed |
| Missed | `dead_tool` (4) | a write tool that nobody calls | its scope not needed |
| Hard negative | `wildcard_fully_used` (5) | a wildcard; read, write and delete tools each use one scope | all needed |
| Hard negative | `legit_admin` (4) | a `keys` resource with a read tool and a destructive admin tool | both needed |
| Hard negative, cut by mistake | `hint_wrong_scope_right` (3) | a tool with a read-only hint that truly writes, and declares write | write needed, the proposal cuts it |
| Hard negative | `multi_resource_reader` (6 tools) | a read-only tool that reads two resources | both needed |

The first three groups test what the rules should catch and what they cannot see. The hard negatives test for false alarms. The planted counts are quotas at the top of `_generate.py`.

## Generator settings (design choices, not measurements)

| Setting | Value | Why |
|---|---|---|
| `N_SERVERS` | 30 | Enough manifests for each profile to appear several times |
| `NO_HINT_SHARE` | 0.25 | Share of ordinary tools written with no annotations |
| resources per server | 3 to 5, drawn from 8 names, plus `keys` where `legit_admin` is planted | |
| `N_CROSS_READERS` | 6 | Servers that get a tool reading two resources |

These were set before the first run. The step scripts do not print them. The data is dense on purpose, so every effect appears often enough to count; it is a test set, not an estimate of how many scopes a real server holds without need.
