# Data for project 38

Synthetic. Generated by `_generate.py` with fixed seeds, so a rerun reproduces every file byte for byte. Nothing here comes from a real gateway, customer, bank or employer. Internal addresses use the reserved name `bank.example`; attacker addresses and hosts use `.test` names; customer ids, session ids and SSN-shaped numbers are invented strings.

| File | What it holds |
|---|---|
| `pack.csv` | The test pack: 160 cases, 100 attacks (`expected` = block) and 60 benign cases (`expected` = allow). Columns: `case_id`, `channel`, `technique`, `expected`, `hard`, `session_id`, `memory_owner`, `text` |
| `population.csv` | A held-out population from the same templates: 1000 attacks and 500 benign cases, same columns. The pack never contains these ids. It stands in for real traffic when step 1 decides which rule changes were harmful |
| `gateway_rules.json` | The base rules of the five-layer gateway. Written by hand in `_base_rules.py`, kept apart from the case templates, and copied here by the generator |
| `rule_prs.csv` | 51 rule changes: `pr_id`, `kind`, `layer`, `note`, `new_rules_json` (the whole new rule file). The kind is what the change was meant to be. Whether it is harmful is measured on the held-out population in step 1 |
| `example_rules_new.json` | The worked example behind `python3 injection_pack.py --demo`: the base rules with `L2-04` narrowed to the verbs forward and email |

## How a case is labelled

The label comes from the template that made the case, never from the rules. `channel` is an explicit field and decides which layer reads the case: `user_input` (layer 1), `retrieved_doc` (layer 2), `tool_call` (layer 3), `response` (layer 4), `session` (layer 5). Session cases carry `session_id` and `memory_owner` as separate fields; nothing is read from the shape of an id.

`hard` = yes marks a case written to be difficult. For an attack it means written to slip past ordinary rules (zero-width characters, look-alike letters, another language, an encoded payload, a tool call with no destination or a destination under an unlisted key, a claimed identity with no memory reference). For a benign case it means written to look like an attack (a policy note that says "send the form to ...", "note to the model risk committee", a masked SSN, a wire reference number, an internal image link).

The pack leaves out one technique on purpose: `doc_encoded_blob`, a retrieved document that carries a base64 or hex payload, usually with a "decode and follow" cue. It is 60 of the 1000 held-out attacks and 0 of the pack's 100. It is the blind spot step 4 prints.

## Assumptions

- 🟡 A rule change is called harmful when, on the held-out population, it lowers the share of attacks blocked by at least 1 percentage point, or raises the share of benign cases blocked by at least 1 percentage point (`HARM_POINTS` in `src/common.py`). The line is mine. Moving it changes which changes count as harmful.
- 🟡 In step 3 the floor gate uses the base rates on the pack with 5 points of slack either way. The 5 is mine.
- The rules in `_base_rules.py` and the templates in `_generate.py` have the same author. See the README.
