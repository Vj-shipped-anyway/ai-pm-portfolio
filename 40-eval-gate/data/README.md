# Data for project 40

Synthetic. Generated by `_generate.py` with a fixed seed, so a rerun reproduces every file byte for byte. Nothing here comes from a real model vendor, bank or employer. The snapshot ids are neutral labels (`vendor-balanced-4-20260214`), not product ids.

| File | What it holds |
|---|---|
| `probes.csv` | The probe set: 30 probes (12 high severity, 8 medium, 10 low), with `slice`, `situation`, `expected_behavior` and `baseline_rate`. The baseline is the pass rate measured from 60 earlier trials per probe on the pinned snapshot |
| `runs.csv` | 64 candidate deploys, one row per probe per run: `run_id`, `probe_id`, `passes` out of `trials` (10 trials per probe), and `served_model`, the snapshot id the response reported |
| `run_pins.csv` | The pin the gate is given for each run. It is the pinned snapshot, except on the 12 announced-swap runs, where the team moved the pin to the new snapshot |
| `run_truth.csv` | The planted event per run and the decision it deserves (`truth_decision`: BLOCK, REVIEW or ALLOW). The label comes from the event that was planted, not from the gate |
| `example_results.csv` | One run in the single-run shape the command reads (no `run_id` column): the first silent swap with a collapsed probe. It is what `python3 eval_gate.py --demo` runs |

Planted events (64): clean 25, announced swap with unchanged behavior 6, silent swap with unchanged behavior 6, silent swap with a broad drop 6, silent swap with a collapsed high-severity probe 5, announced swap with a broad drop 3, announced swap with a collapsed probe 3, moderate drift behind an unchanged id 3, subtle drift behind an unchanged id 3, results missing a high-severity probe 2, results missing only low-severity probes 2. Truth: 25 BLOCK, 8 REVIEW, 31 ALLOW.

How the truth is set (a judgment call, stated so you can disagree):

- A silent swap blocks even when the probes score the same. The rule is that an id change nobody announced is read before it ships. That is a policy, not a measurement of harm.
- An announced swap with unchanged behavior is fine. An announced swap that regressed is not.
- Drift behind an unchanged id is REVIEW, moderate or subtle. A run with only low-severity probes missing is REVIEW; one missing a high-severity probe is BLOCK.

How the runs are generated (🟡 modeled: every size below is an assumption I chose, not an observation of any vendor):

- Each probe has a latent pass rate (0.95 to 1.0 high, 0.90 to 0.95 medium, 0.82 to 0.90 low). Passes are sampled, 10 trials each. The gate sees counts only.
- Broad drop: every affected probe loses 8 to 15 points of latent rate. Moderate drift: 3.5 to 5 points. Subtle drift: 1.5 to 2.5 points. Collapse: one or two high-severity probes fall to a latent rate of 0.15 to 0.40.
- Each silent flat or broad swap has an even chance of being a partial rollout (7 of the 12 are): only 10 to 20 of the 30 probes are served by the new id, the rest by the pin.
- The baseline in `probes.csv` carries its own sampling noise, as a real one would.
