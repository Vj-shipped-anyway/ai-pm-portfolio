# Data for project 57

Synthetic. Generated by `_generate.py` with a fixed seed (`SEED = 57`), so a rerun reproduces every file byte for byte. Nothing here comes from a real bank, company, customer or employer; the counterparty names are invented from syllables.

| File | What it holds |
|---|---|
| `ledger_a.csv` | 383 lines of a bank statement for one month: `a_id`, `value_date`, `amount`, `currency`, `counterparty`, `narrative`, `customer_ref` |
| `ledger_b.csv` | 438 lines of the company's cash book: `b_id`, `posting_date`, `amount`, `currency`, `counterparty`, `reference`, `batch_id`, `memo` |
| `truth.csv` | The answer key, 448 links: `link_id`, `kind`, `truth_status` (match, a_only, b_only), `a_ids`, `b_ids` (ids joined with `+`). Every line appears in exactly one link |
| `example_ledger_a.csv`, `example_ledger_b.csv`, `example_approvals.csv` | The worked month behind `python3 recon_agent.py --demo`: 11 bank lines, 15 book lines and 5 recorded approvals (one valid fee approval, one valid batch approval, one rejection, one for a proposal that does not exist, one by the agent itself) |

Amounts are signed from the cash account's side: money in is positive. Dates are ISO. The batch id is an explicit column on the book side; the bank carries it in `customer_ref`.

## How the answer key is made

The generator decides what happened first (a payment, a batch, a bank fee, an outstanding item) and then writes each ledger's view of it with that ledger's own noise: a date lag, a different reference format, an upper-case bank name with an abbreviation, a fee netted by the bank. It never calls the matching rules. The key is the generator's account of what happened, not a label from a real reconciliation. Amounts are unique across the month except where a kind needs a repeat, so no match arises by accident, which also makes the data cleaner than a real month.

## Planted kinds

| Kind | Count | What it is | Truth |
|---|---|---|---|
| exact | 110 | Same date, amount and reference | match |
| large | 10 | As exact, amounts from 10001.00 to 59999.99 | match |
| date_lag | 60 | Book date 1 to 3 days from the bank date | match |
| ref_format | 40 | Same reference written another way (case, hyphen, zero padding) | match |
| fee_netted | 20 | Bank credit is the book amount less 1.50, 2.50 or 15.00 | match |
| batch | 12 | One bank line, 3 or 4 book lines sharing a batch id | match (one bank line to several) |
| ref_typo | 15 | Bank reference one edit from the book reference | match |
| no_ref | 30 | Blank reference on the bank side (about two thirds) or the book side | match |
| payer_differs | 8 | Same reference and amount, a different payer name at the bank | match |
| dup_b | 8 | An exact pair plus a second, identical book line | match, and the spare is b_only |
| twin_payments | 6 | One bank line, two book lines with the same amount 2 days apart, the bank line between them | match to one, the other is b_only |
| split_no_batch | 4 | One bank line, 2 or 3 book lines with no batch id | match; planted miss |
| out_of_window | 6 | Same reference and amount, dates 4 to 6 days apart | match; planted miss |
| ref_garbled | 4 | Bank reference two characters from the book reference | match; planted miss |
| no_ref_abbrev | 4 | Blank bank reference; the bank writes MFG for Manufacturing | match; planted miss |
| lookalike_conflict | 10 | Same amount, name and window, references three or more characters apart | a_only and b_only; hard negative |
| near_ref_distinct | 6 | Same amount, name and window, references one edit apart, two real invoices | a_only and b_only; hard negative |
| currency_clash | 5 | Same amount, reference and date, USD at the bank and EUR in the book | a_only and b_only; hard negative |
| a_only | 25 | Bank fees and interest with no book line | a_only |
| b_only | 30 | Payments in the book that have not cleared | b_only |

Two groups are hard on purpose: the hard negatives test for a wrong match, and the planted misses test for a true match the rules cannot reach. Ids are assigned after sorting by date, so a duplicate book line always has a higher id than the line it copies.

## Assumptions the tool carries (🟡 modeled, none taken from a rule)

The date window is 3 days. A match above 10000.00 needs a person. The bank may net 1.50, 2.50 or 15.00 from a credit. A batch has 2 to 6 book lines. Only `ref_exact` may post without a person. The generator uses these same fee amounts and the same window, so the tool knows what the data holds; a real bank's fees would have to be read from its schedule.
